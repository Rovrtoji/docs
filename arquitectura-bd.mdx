## Dominio: Autenticación y usuarios

Tablas que sostienen el login, la sesión, el modelo RBAC (roles, permisos, aplicaciones), la estructura organizacional y la auditoría.

<AccordionGroup>
  <Accordion title="usuarios" icon="user">
    **Para qué sirve:** guarda a las personas que entran al sistema (empleados, ejecutivos, administradores).

    **Campos:**
    - `id` — número único del usuario
    - `username` — nombre de inicio de sesión (único)
    - `email` — correo electrónico (único)
    - `password_hash` — contraseña cifrada
    - `aplicacion` — código de la aplicación a la que pertenece
    - `nickname` — apodo opcional
    - `full_name` — nombre completo
    - `employee_code` — código interno de empleado (único)
    - `job_title` — puesto en texto libre
    - `area` — área o departamento en texto libre
    - `salary` — sueldo (número con decimales, opcional)
    - `activo` — sí/no, si la cuenta está habilitada
    - `ultimo_acceso` — fecha y hora del último inicio de sesión
    - `intentos_fallidos` — número de intentos fallidos consecutivos
    - `bloqueado_hasta` — fecha y hora hasta la que la cuenta queda bloqueada
    - `token_api_key` — clave para acceso por API (único)
    - `descripcion` — texto libre con notas
    - `position_id` — referencia al puesto formal
    - `manager_user_id` — referencia al jefe directo (también un usuario)
    - `created_at`, `updated_at` — fechas de alta y modificación

    **Se relaciona con:**
    - Tabla `positions` (por el puesto)
    - Otra fila de `usuarios` (su jefe directo)
    - Tabla `usuarios_roles` (los roles asignados)
    - Tabla `usuarios_permisos_directos` (permisos otorgados o denegados directamente)
    - Casi todas las tablas que registran quién creó, asignó o cargó un dato
  </Accordion>

  <Accordion title="roles" icon="users-round">
    **Para qué sirve:** guarda los grupos de permisos (por ejemplo, `super_admin`, `manager`, `usuario`).

    **Campos:**
    - `id` — número único del rol
    - `nombre` — nombre del rol (único)
    - `descripcion` — para qué sirve el rol
    - `activo` — sí/no
    - `created_at`, `updated_at` — fechas de alta y modificación

    **Se relaciona con:**
    - Tabla `roles_permisos` (qué permisos tiene el rol)
    - Tabla `usuarios_roles` (qué usuarios tienen este rol)
    - Tabla `roles_applications` (a qué aplicaciones da acceso)
  </Accordion>

  <Accordion title="permisos" icon="key">
    **Para qué sirve:** lista las acciones que se pueden permitir o negar (leer, crear, editar, exportar, etc.).

    **Campos:**
    - `id` — número único del permiso
    - `nombre` — clave corta (única, por ejemplo `usuarios_read`)
    - `recurso` — sobre qué actúa (por ejemplo `usuarios`)
    - `accion` — qué se permite (`read`, `write`, `delete`)
    - `descripcion` — explicación legible
    - `activo` — sí/no
    - `created_at` — fecha y hora de alta

    **Se relaciona con:**
    - Tabla `roles_permisos` (qué roles incluyen este permiso)
    - Tabla `usuarios_permisos_directos` (qué usuarios lo tienen otorgado o denegado directamente)
    - La combinación `recurso + accion` debe ser única
  </Accordion>

  <Accordion title="roles_permisos" icon="link">
    **Para qué sirve:** une roles con permisos. Una fila por cada permiso que tiene un rol.

    **Campos:**
    - `id` — número único de la asignación
    - `role_id` — referencia al rol
    - `permiso_id` — referencia al permiso
    - `created_at` — fecha y hora en que se otorgó

    **Se relaciona con:**
    - Tabla `roles`
    - Tabla `permisos`
    - Un mismo permiso no puede asignarse dos veces al mismo rol
  </Accordion>

  <Accordion title="usuarios_roles" icon="link">
    **Para qué sirve:** une usuarios con roles. Un usuario puede tener varios roles.

    **Campos:**
    - `id` — número único de la asignación
    - `usuario_id` — referencia al usuario
    - `role_id` — referencia al rol
    - `asignado_por` — qué usuario hizo la asignación (opcional)
    - `asignado_en` — fecha y hora en que se asignó

    **Se relaciona con:**
    - Tabla `usuarios`
    - Tabla `roles`
    - Un mismo rol no se asigna dos veces al mismo usuario
  </Accordion>

  <Accordion title="usuarios_permisos_directos" icon="shield-check">
    **Para qué sirve:** permisos que se otorgan o se niegan directamente a un usuario, sin pasar por un rol.

    **Campos:**
    - `id` — número único
    - `usuario_id` — referencia al usuario
    - `permiso_id` — referencia al permiso
    - `tipo` — `grant` (otorgado) o `deny` (denegado)
    - `asignado_por` — qué usuario hizo la asignación (opcional)
    - `asignado_en` — fecha y hora

    **Se relaciona con:**
    - Tabla `usuarios`
    - Tabla `permisos`
  </Accordion>

  <Accordion title="applications" icon="app-window">
    **Para qué sirve:** catálogo de las aplicaciones del ecosistema (Finanzas, Operaciones, CRM, RH).

    **Campos:**
    - `id` — número único
    - `code` — código corto (único, por ejemplo `finanzas`)
    - `name` — nombre visible
    - `description` — descripción larga
    - `short_description` — descripción corta para tarjetas
    - `base_url` — URL pública de la aplicación
    - `icon` — icono de la interfaz
    - `color` — color principal
    - `active` — sí/no
    - `display_order` — orden de aparición
    - `created_at`, `updated_at` — fechas de alta y modificación

    **Se relaciona con:**
    - Tabla `application_menu_views` (los menús de cada app)
    - Tabla `roles_applications` (qué roles tienen acceso a esta app)
  </Accordion>

  <Accordion title="roles_applications" icon="link">
    **Para qué sirve:** define qué roles pueden ver qué aplicaciones.

    **Campos:**
    - `id` — número único
    - `role_id` — referencia al rol
    - `application_id` — referencia a la aplicación
    - `created_at` — fecha y hora

    **Se relaciona con:**
    - Tabla `roles`
    - Tabla `applications`
  </Accordion>

  <Accordion title="application_menu_views" icon="menu">
    **Para qué sirve:** lista de elementos de menú de cada aplicación (puede ser jerárquica, hay submenús).

    **Campos:**
    - `id` — número único
    - `application_id` — referencia a la aplicación dueña del menú
    - `parent_id` — referencia al elemento padre (si es un submenú)
    - `code` — código jerárquico (por ejemplo `inventario.items`)
    - `label` — texto a mostrar
    - `icon` — icono
    - `route` — ruta de la aplicación
    - `permission_required` — clave del permiso que el usuario debe tener
    - `display_order` — orden de aparición
    - `active` — sí/no
    - `created_at` — fecha y hora de alta

    **Se relaciona con:**
    - Tabla `applications`
    - Sí misma (jerarquía padre/hijo)
  </Accordion>

  <Accordion title="active_sessions" icon="circle-user">
    **Para qué sirve:** sesiones abiertas del usuario (tokens activos).

    **Campos:**
    - `id` — número único
    - `user_id` — referencia al usuario
    - `token_hash` — huella criptográfica del token (única)
    - `ip_address` — dirección IP desde donde se inició
    - `user_agent` — texto que identifica el navegador o app
    - `created_at` — cuándo se creó
    - `expires_at` — cuándo expira
    - `is_active` — sí/no

    **Se relaciona con:**
    - Tabla `usuarios`
  </Accordion>

  <Accordion title="password_reset_tokens" icon="lock-keyhole">
    **Para qué sirve:** tokens temporales para que un usuario reestablezca su contraseña.

    **Campos:**
    - `id` — número único
    - `user_id` — referencia al usuario
    - `token_hash` — huella criptográfica del token (única)
    - `expires_at` — fecha y hora de expiración
    - `used` — sí/no, si ya fue utilizado
    - `created_at` — fecha y hora de alta

    **Se relaciona con:**
    - Tabla `usuarios`
  </Accordion>

  <Accordion title="auth_handoff_tokens" icon="arrow-up-right-from-square">
    **Para qué sirve:** tokens cortos para pasar la sesión de una app a otra sin volver a iniciar sesión.

    **Campos:**
    - `id` — número único
    - `user_id` — referencia al usuario
    - `code_hash` — huella del código entregado (único)
    - `target_app_code` — código de la aplicación destino
    - `expires_at` — fecha y hora de expiración
    - `used_at` — fecha y hora en que se canjeó
    - `ip_address` — dirección IP
    - `user_agent` — identificación del navegador o app
    - `created_at` — fecha y hora de alta

    **Se relaciona con:**
    - Tabla `usuarios`
  </Accordion>

  <Accordion title="departments" icon="building">
    **Para qué sirve:** catálogo de departamentos de la empresa.

    **Campos:**
    - `id` — número único
    - `name` — nombre del departamento (único)
    - `is_active` — sí/no
    - `created_at` — fecha y hora de alta

    **Se relaciona con:**
    - Tabla `positions` (los puestos pertenecen a un departamento)
    - Tabla `area_managers` (quiénes son responsables del departamento)
  </Accordion>

  <Accordion title="positions" icon="briefcase">
    **Para qué sirve:** catálogo de puestos por departamento.

    **Campos:**
    - `id` — número único
    - `name` — nombre del puesto
    - `department_id` — referencia al departamento
    - `is_active` — sí/no
    - `created_at` — fecha y hora de alta

    **Se relaciona con:**
    - Tabla `departments`
    - Tabla `usuarios` (el puesto formal del usuario)
    - El mismo nombre de puesto no se repite dentro del mismo departamento
  </Accordion>

  <Accordion title="area_managers" icon="user-cog">
    **Para qué sirve:** registro de qué usuarios son jefes de un departamento.

    **Campos:**
    - `id` — número único
    - `user_id` — referencia al usuario que ejerce de jefe
    - `department_id` — referencia al departamento
    - `is_active` — sí/no
    - `created_at` — fecha y hora de alta

    **Se relaciona con:**
    - Tabla `usuarios`
    - Tabla `departments`
    - Un usuario no puede aparecer dos veces como jefe del mismo departamento
  </Accordion>

  <Accordion title="user_notifications" icon="bell">
    **Para qué sirve:** notificaciones internas del sistema dirigidas a un usuario (campanita).

    **Campos:**
    - `id` — número único
    - `user_id` — usuario destinatario
    - `type` — tipo de notificación
    - `title` — título
    - `body` — texto largo
    - `link` — enlace opcional
    - `read` — sí/no, si ya se leyó
    - `created_at` — fecha y hora

    **Se relaciona con:**
    - Tabla `usuarios`
  </Accordion>

  <Accordion title="audit_log" icon="scroll-text">
    **Para qué sirve:** bitácora de cambios sensibles realizados en el sistema (quién hizo qué y cuándo).

    **Campos:**
    - `id` — número único
    - `user_id` — usuario que realizó la acción (opcional, puede ser sistema)
    - `action` — qué se hizo
    - `resource` — sobre qué recurso
    - `resource_id` — identificador del recurso afectado
    - `details` — datos estructurados con detalles (cambios antes/después)
    - `ip_address` — dirección IP
    - `user_agent` — identificación del navegador o app
    - `created_at` — fecha y hora

    **Se relaciona con:**
    - Tabla `usuarios`
  </Accordion>
</AccordionGroup>

## Dominio: Clientes (CRM)

Tabla maestra de clientes (heredada de Odoo) y sus tablas satélite: cuentas de facturación, RFCs, cuentas B2B en GPS, notas internas y contactos.

<AccordionGroup>
  <Accordion title="iquo_cliente" icon="user-search">
    **Para qué sirve:** catálogo central de clientes de la empresa. Es la tabla maestra del CRM. Originalmente proviene de Odoo; ahora se gestiona aquí.

    **Campos:**
    - `id` — número único del cliente
    - `name` — razón social o nombre comercial (único)
    - `ejecutivoid` — referencia al ejecutivo en Odoo (sistema externo)
    - `vendoruserid` — referencia al vendedor en Odoo (sistema externo)
    - `empresafactura` — empresa que factura (`soluciones` por defecto)
    - `notas` — texto libre
    - `tipocliente` — tipo o segmento
    - `calle`, `numero`, `colonia`, `municipio`, `estado`, `codigopostal` — dirección
    - `representantelegal` — nombre del representante legal
    - `telefono`, `email`, `puesto`, `giro` — datos de contacto y actividad
    - `create_uid`, `write_uid` — usuario de Odoo que creó/modificó (sistema externo)
    - `create_date`, `write_date` — fechas de creación y modificación en origen

    **Se relaciona con:**
    - Tabla `cliente_billing_accounts` (cuentas de facturación)
    - Tabla `cliente_client_identifications` (RFC/identificación fiscal)
    - Tabla `cliente_b2b_accounts` (cuentas dentro del sistema GPS)
    - Tabla `cliente_notas` (anotaciones internas)
    - Tabla `cliente_contacto` (contactos del cliente)
    - Tabla `work_orders` (órdenes de trabajo)
    - Tabla `invoices` (facturas)
    - Tabla `ingresos` (pagos recibidos)
    - Tablas `installation_cost_ledger` e `installation_payment_batch_items`
  </Accordion>

  <Accordion title="billing_accounts" icon="receipt">
    **Para qué sirve:** cuentas de facturación abstractas (un mismo cliente puede tener varias).

    **Campos:**
    - `id` — número único
    - `name` — nombre de la cuenta
    - `ammount` — monto asociado (número con decimales)
    - `created_at`, `updated_at` — fechas de alta y modificación

    **Se relaciona con:**
    - Tabla `cliente_billing_accounts` (intermediario con el cliente)
    - Tabla `cms_unidades` (la cuenta puede estar ligada a unidades GPS)
  </Accordion>

  <Accordion title="cliente_billing_accounts" icon="link">
    **Para qué sirve:** une un cliente con sus cuentas de facturación.

    **Campos:**
    - `id` — número único
    - `cliente_id` — referencia al cliente
    - `billing_account_id` — referencia a la cuenta de facturación
    - `created_at`, `updated_at` — fechas

    **Se relaciona con:**
    - Tabla `iquo_cliente`
    - Tabla `billing_accounts`
    - Una combinación cliente+cuenta no puede aparecer dos veces
  </Accordion>

  <Accordion title="cliente_client_identifications" icon="id-card">
    **Para qué sirve:** RFC o identificaciones fiscales de los clientes (un cliente puede tener varios RFC con distintas razones sociales).

    **Campos:**
    - `id` — número único
    - `cliente_id` — referencia al cliente
    - `client_identification` — RFC u otro identificador (único en toda la tabla)
    - `legal_entity_code` — código de la razón social (a qué empresa se factura)
    - `created_at` — fecha y hora de alta

    **Se relaciona con:**
    - Tabla `iquo_cliente`
    - Tabla `legal_entities` (a través del código)
  </Accordion>

  <Accordion title="cliente_b2b_accounts" icon="building-2">
    **Para qué sirve:** une un cliente con cuentas externas del sistema GPS (B2B).

    **Campos:**
    - `id` — número único
    - `cliente_id` — referencia al cliente
    - `b2b_account_id` — identificador en el sistema externo
    - `b2b_account_name` — nombre legible
    - `created_at` — fecha y hora de alta

    **Se relaciona con:**
    - Tabla `iquo_cliente`
    - Una misma cuenta b2b no se duplica para el mismo cliente
  </Accordion>

  <Accordion title="cliente_notas" icon="sticky-note">
    **Para qué sirve:** anotaciones manuales que el equipo agrega sobre un cliente (CRM).

    **Campos:**
    - `id` — número único
    - `cliente_id` — referencia al cliente
    - `nota` — texto de la nota
    - `created_by` — usuario que la creó
    - `created_at` — fecha y hora

    **Se relaciona con:**
    - Tabla `iquo_cliente`
    - Tabla `usuarios`
  </Accordion>

  <Accordion title="cliente_contacto" icon="contact">
    **Para qué sirve:** contactos (personas) ligados a un cliente.

    **Campos:**
    - `id` — número único
    - `name` — nombre
    - `telefonomovil`, `telefonofijo` — teléfonos
    - `correo` — correo electrónico (único en toda la tabla)
    - `referencia`, `ciudad`, `direccion`, `codigopostal` — datos de dirección
    - `notas` — texto libre
    - `clienteid` — referencia al cliente
    - `tipocontacto` — tipo de contacto
    - `userodoo` — referencia al usuario de Odoo (sistema externo)
    - `create_uid`, `write_uid` — usuario que creó/modificó en Odoo
    - `create_date`, `write_date` — fechas de origen

    **Se relaciona con:**
    - Tabla `iquo_cliente`
    - El nombre y el correo deben ser únicos a nivel global
  </Accordion>
</AccordionGroup>

## Dominio: Finanzas

Razones sociales, facturas sincronizadas desde Alegra, ingresos recibidos, gastos, costos de instalación y pagos a técnicos.

<AccordionGroup>
  <Accordion title="legal_entities" icon="building">
    **Para qué sirve:** catálogo de razones sociales de la empresa. Cada factura se emite desde una de estas razones sociales.

    **Campos:**
    - `id` — identificador único (formato UUID, generado automáticamente)
    - `code` — código corto (único, por ejemplo `soluciones`)
    - `business_name` — razón social completa
    - `tax_id` — RFC (con valor inicial `PENDING` si está en proceso)
    - `tax_regime` — régimen fiscal
    - `address_street`, `address_city`, `address_state`, `address_zip` — dirección
    - `country` — país de dos letras (por defecto `MX`)
    - `is_active` — sí/no
    - `display_order` — orden de aparición
    - `created_at`, `updated_at` — fechas de alta y modificación

    **Se relaciona con:**
    - Tabla `invoices` (las facturas se asocian a una razón social)
    - Tabla `cliente_client_identifications` (los RFC del cliente pueden ligarse a la razón social que les factura)
  </Accordion>

  <Accordion title="invoices" icon="file-text">
    **Para qué sirve:** facturas sincronizadas desde Alegra (sistema externo de facturación).

    **Campos:**
    - `id` — número único interno
    - `alegra_id` — identificador en Alegra (único)
    - `company_code` — código de la razón social emisora
    - `client_name` — nombre del cliente en Alegra
    - `client_identification` — RFC del cliente
    - `cliente_id` — referencia al cliente en el CRM
    - `invoice_number` — folio de la factura
    - `invoice_date` — fecha de la factura
    - `price_unit`, `quantity` — precio unitario y cantidad
    - `payment_date`, `payment_status`, `status` — fechas y estados
    - `anotation` — anotaciones
    - `subtotal`, `tax_amount`, `total` — montos
    - `mongo_id` — referencia al documento original en MongoDB
    - `sync_timestamp` — última sincronización
    - `raw_json` — copia íntegra del documento original
    - `created_at`, `updated_at` — fechas

    **Se relaciona con:**
    - Tabla `legal_entities` (por la razón social)
    - Tabla `iquo_cliente` (por el cliente)
    - Tabla `ingresos` (los pagos recibidos pueden ligarse a una factura)
  </Accordion>

  <Accordion title="ingresos" icon="circle-dollar-sign">
    **Para qué sirve:** pagos recibidos de los clientes (depósitos bancarios).

    **Campos:**
    - `id` — número único
    - `fecha` — fecha del depósito
    - `monto` — monto recibido
    - `banco` — banco origen
    - `cuenta` — cuenta de destino
    - `cliente_id` — referencia al cliente (opcional)
    - `factura_id` — referencia a la factura (opcional, único: una factura solo se paga una vez)
    - `uploaded_by` — usuario que cargó el ingreso
    - `updated_by` — último usuario que lo modificó
    - `created_at`, `updated_at` — fechas

    **Se relaciona con:**
    - Tabla `iquo_cliente`
    - Tabla `invoices`
    - Tabla `usuarios` (quién cargó y quién modificó)
  </Accordion>

  <Accordion title="expenses" icon="file-minus">
    **Para qué sirve:** registro mínimo de facturas de gasto. Sirve para ligar inventario comprado a una factura.

    **Campos:**
    - `id` — número único
    - `invoice_number` — folio de la factura de compra (único)

    **Se relaciona con:**
    - Tabla `inventory_items` (los items pueden venir de un gasto)
    - Tabla `inventory_item_history`
  </Accordion>

  <Accordion title="installation_payment_batches" icon="hand-coins">
    **Para qué sirve:** lotes de pagos a técnicos por instalaciones. Cada lote agrupa varias órdenes pagadas a un técnico.

    **Campos:**
    - `id` — número único
    - `folio` — folio del lote (único)
    - `payment_date` — fecha del pago
    - `technician_id` — referencia al técnico
    - `payment_amount` — monto total del pago
    - `voucher_url` — URL del comprobante
    - `note` — texto libre
    - `status` — estado (`paid` por defecto)
    - `created_by` — usuario que creó el lote
    - `created_at`, `updated_at` — fechas

    **Se relaciona con:**
    - Tabla `technicians`
    - Tabla `usuarios`
    - Tabla `installation_payment_batch_items` (las órdenes incluidas)
  </Accordion>

  <Accordion title="installation_payment_batch_items" icon="list">
