## Qué es el sistema

Plataforma interna **ERP/CRM** de una empresa de **rastreo y soluciones GPS B2B**. Reemplaza progresivamente el ERP legacy **Odoo 17** por código propio. Cubre la operación completa: clientes, instalaciones, soporte, inventario, finanzas y asistencia del personal.

**Idioma del proyecto:** español (código, comentarios y documentación).

## Arquitectura en una frase

Varias **apps web React** consumen un **backend FastAPI asíncrono** sobre **PostgreSQL**, con **Redis** (cache) y **S3** (archivos). Dos **servicios independientes** (facturación, asistencia) comparten la misma base de datos pero corren como procesos separados.

```
Apps web (React+Vite)  ──HTTPS, cookie httpOnly + CSRF──▶  Backend FastAPI
                                                              │
                          PostgreSQL ◀── Redis ── S3 ─────────┘
                              ▲
                  AlegraPy · Checador  (servicios satélite)
```

## Backend (FastAPI)

- **Stack:** FastAPI + SQLAlchemy 2 async + asyncpg + Alembic + Pydantic v2 + Redis + APScheduler + boto3 (S3). Python ≥ 3.12. Paquete `app/` (layout plano).
- **Tamaño:** ~30 módulos de routers, **162 paths / 231 operaciones**, **232 schemas**. OpenAPI **3.1.0** generado del código real (siempre sincronizado).
- **Puerto dev:** 8090/8091.

**Módulos de API** (routers `app/presentation/api/v1/`):

`auth`, `usuarios`, `users_contract`, `roles`, `roles_v2`, `permissions`, `permisos`, `applications`, `audit`, `catalogs`, `clientes`, `cms_unificado`, `billing_accounts`, `legal_entities`, `ingresos`, `billing`, `alegra_invoices`, `installation_payments`, `inventory`, `work_orders`, `work_order_evidence`, `operations_dashboard`, `equipmentpurchases_dashboard`, `financial_dashboard`, `dashboard`, `filters`, `notifications`, `storage`, `support`, `attendance`, `health`, `dependencies`.

<Warning>
  **Auth (patrón oficial F3-02b):** cookie **httpOnly** (`token`, `csrf_token`) + **CSRF double-submit** (header `X-CSRF-Token` en métodos mutantes). El frontend usa `credentials: 'include'`. **No** usar Bearer token ni `localStorage`.
</Warning>

**Handoff entre apps:** token SHA-256, un solo uso, TTL 60 s, ligado a IP/UA. Auditable con `GET /api/v1/audit-log?resource=auth_handoff`.

## Servicios independientes

<AccordionGroup>
  <Accordion title="AlegraPy — facturación" icon="receipt">
    - Sincroniza facturas de la **API de Alegra** (`api.alegra.com`) hacia la tabla `invoices` de PostgreSQL, **3:00 AM hora CDMX**, diario.
    - Reemplazó el sync anterior por **MongoDB** (ya eliminado). Ya **no usa Mongo**.
    - Corre como **contenedor separado** (`services/alegrapy/`), no en el scheduler del backend. Comparten solo PostgreSQL. Deploy Docker + Dokploy (`dokploy-network`).
    - Config clave: `CRON_AT_HOUR=3`, `TZ_CRON=America/Mexico_City`, `SKIP_MONGO=true`, `SKIP_REDIS=true`. Empresas normalizadas a `soluciones` / `ramsa` (minúscula).
    - `cliente_id` lo mapea el backend (`AUTO_BACKFILL_INVOICES`), no AlegraPy.

    Ver: [Arquitectura AlegraPy](/alegrapy-arquitectura).
  </Accordion>

  <Accordion title="Checador — asistencia" icon="clock">
    - App + backend propios. Login con **JSON** `{ identifier, password }` (no form-urlencoded).
    - Registro de asistencia exige header **`Idempotency-Key`**; evidencias en S3.
    - El CORS del backend debe permitir `Idempotency-Key` en `allow_headers` (fix PR #30).
  </Accordion>

</AccordionGroup>

## Base de datos

- **Motor:** PostgreSQL (una sola base compartida por backend, portal y servicios).
- **Migraciones:** Alembic (`AUTO_MIGRATE=true` aplica en startup).
- **Dominios documentados:** Auth/RBAC, Catálogos, Clientes, CMS (unidades/hardware), Finanzas (invoices, ingresos, pagos), Operaciones (work orders, inventario), Attendance, Soporte, Portal Cliente.

**Aislamiento multi-tenant del portal:** el JWT lleva `cliente_id`; todas las queries filtran por tenant; recurso de otro tenant devuelve **404 (no 403)**.

## Convenciones y decisiones permanentes

<Steps>
  <Step title="Auth">
    Cookie httpOnly + CSRF double-submit. Nunca Bearer/localStorage en frontend.
  </Step>
  <Step title="UUI Input password">
    `type="password"` ya trae toggle de ojito nativo; no agregar botón manual.
  </Step>
  <Step title="GET /api/v1/roles">
    Devuelve `{id:int, nombre:str}` (no `name`). Las interfaces TS deben coincidir.
  </Step>
  <Step title="Select de UUI dentro de Tabs">
    Crashea; mover el `Select` fuera o usar `key` dinámica.
  </Step>
  <Step title="Catálogos">
    `catalog_service.{create,update,soft_delete}_position` retornan `dict`, no objeto.
  </Step>
  <Step title="Backend sin auto-reload en prod">
    Reiniciar uvicorn tras cada deploy.
  </Step>
  <Step title="Documentación">
    Toda doc nueva en `proyecto interno/` (`.md` + `.html`/`.mdx`), no en los repos de código.
  </Step>
  <Step title="Código">
    Sin comentarios narrativos; solo tags de ticket (`# F1-XX`). SOLID, reusables primero, tokens semánticos.
  </Step>
  <Step title="No CLIs nuevas">
    Preferir Python con el venv existente.
  </Step>
  <Step title="Secretos">
    `.env`/`.env.bak` jamás se commitean (verificar `.gitignore`).
  </Step>
</Steps>
