## 5. Cambios técnicos transversales (post-cierre)

Estos cambios afectaron a hub **y** backoffice (y todas las apps del monorepo), no salen del plan v2.1 pero impactan el despliegue.

### 5.1 Migración auth a cookie httpOnly + CSRF (Tricell F3-02b)

**Commits clave:** `26311af`, `bf5f75b`, `c0afee4`, `6776cde` (Merge PR #6), `07b36b1` (Merge PR #7), `f50f5a5`

- Cookies `token` y `csrf_token` como httpOnly por backend
- Frontend usa `credentials: 'include'` + header `X-CSRF-Token` en métodos mutantes
- `ApiClientOptions` ya no recibe `token?` (limpiado en `c0afee4`)
- `localStorage.getItem('token')` eliminado de los callsites del backoffice y hub

### 5.2 Limpieza DT-017 — typecheck + lint

**Commits:** `7d2cd32`, `f1057f0` (Merge PR #9), `66d0ad2`, `027ec29` (Merge PR #10), `1c0efcd`, `383a20f`

- Biome auto-fix masivo
- Sanitization de `tsconfig.json` por app (rootDir, paths)
- `SelectItemType` callbacks con tipado correcto (DT-017b)
- `type="button"` agregado a 122 botones (`useButtonType`)
- Residuales `noArrayIndexKey`, a11y modal, directivas tailwind

### 5.3 Super_admin también accede al hub (Opción A)

**Commit:** `9645df0`

Decisión del usuario tras feedback: cualquier usuario, incluido `super_admin`, debe poder ingresar al `/launcher` del hub (antes era redirigido directo al backoffice). El backoffice sigue siendo el destino por default vía handoff, pero el launcher queda accesible.

### 5.4 Fix CSRF en handoff (descubierto post-cierre)

**Commit:** `8fb4874`

Bug detectado durante prueba real con Chrome DevTools MCP: el botón "abrir app" del launcher **no enviaba `X-CSRF-Token`** al `POST /api/v1/auth/handoff`. El backend respondía **403 csrf token missing or mismatched** y el `catch` del hub caía al fallback silencioso `window.location.href = app.base_url`, dejando al usuario en bucle hub → app sin sesión → hub.

**Solución:**
- Import de `readCookie`, `CSRF_COOKIE_NAME`, `CSRF_HEADER_NAME` desde `@finanzas/api-client`
- `credentials: 'include'` en el fetch
- Header `X-CSRF-Token` leído de la cookie `csrf_token`

Verificado end-to-end: login con `ricardo` → click Finanzas → llega a `localhost:5175` con sesión iniciada.

## 8. Decisiones técnicas que el equipo debe conocer

Estas decisiones quedaron grabadas en memoria persistente y aplican a cualquier trabajo futuro sobre estas áreas:

1. **Cookie httpOnly + CSRF double-submit (F3-02b)** es el patrón oficial de auth en todo el frontend. **No** usar Bearer token en frontend ni guardarlo en localStorage.
2. **UUI Input `type="password"` ya trae toggle nativo de ojito.** No agregar botón manual (causa duplicación del Fix D-4).
3. **`GET /api/v1/roles` devuelve `{id:int, nombre:str}`** (no `name`). Las interfaces TS deben coincidir o no matchean (causa del bug "Da acceso a:" que no aparecía).
4. **`Select` de UUI dentro de `<Tabs>` crashea** con `selectionManager` al cambiar de panel. Mover el `Select` fuera del `Tabs` o dar `key` dinámica.
5. **`catalog_service.{create,update,soft_delete}_position` y `{create,delete}_area_manager` retornan `dict`**, no objeto. Acceder con `pos["id"]`, no `pos.id`.
6. **Backend en puerto 8090 debe reiniciarse manualmente** para cargar código nuevo (no tiene auto-reload). Esto fue causa de varios falsos negativos en QA.
7. **Token de handoff:** SHA256 + TTL 60s + single-use + binding IP/UA. Audit con `resource=auth_handoff`.
8. **`SECURITY_ACTIONS`** que disparan notificación a todos los super_admin + auditor (7): `user_delete`, `role_delete`, `role_permissions_set`, `role_applications_set`, `revoke_session`, `login_failed`, `application_delete`.

## 10. Cómo desplegar y probar

### 10.1 Pre-deploy

```bash
# Backend
cd finananzaspython
source .venv/bin/activate
alembic upgrade head           # aplica j1a2…user_notifications y j2b3…position_manager
pytest tests/ -q               # debe dar 42/42 PASS
```

### 10.2 Despliegue

1. Detener y reiniciar `uvicorn main:app --port 8090` (sin `--reload` en prod).
2. Rebuildear apps frontend: `pnpm build:hub` y `pnpm build:backoffice`.
3. Servir los bundles con nginx (config ya documentada).

### 10.3 Smoke test post-deploy (10 minutos)

1. **Hub login** — abrir `/login`, ingresar `ricardo / <pass>`, confirmar redirect a backoffice.
2. **Empleado** — usuario sin rol admin → debe aterrizar en `/launcher` con sus apps.
3. **Launcher** — click en Finanzas → debe abrir Finanzas con sesión (sin pasar por login).
4. **Forgot password** (hub y backoffice) — flujo idle → sent.
5. **Backoffice notificaciones** — disparar `role_delete` vía API → ver badge en la campanita del header.
6. **Backoffice users** — abrir un usuario, ver Puesto + Jefe directo, abrir modal editar, confirmar Selects pueblan.
7. **Backoffice roles** — verificar "Da acceso a: App1, App2" en tab Roles del detail.
8. **Backoffice catalogs** — abrir departamentos, confirmar contador "N puestos · M usuarios".
9. **Audit log** — `GET /api/v1/audit-log?resource=auth_handoff` debe mostrar actividad del handoff.
