> Este anexo complementa la documentación principal de la base de datos
> (`arquitectura-bd.html` / `arquitectura-bd-simple.md`).
>
> Documenta las tablas que el servicio **Central de Monitoreo**
> (migración del legacy `monitoreocompleto` de Odoo 17 a React + FastAPI)
> debe crear como **propias** en el backend.
>
> **NO se duplican** las tablas que ya existen en el ERP:
>
> | Concepto legacy (Odoo) | Tabla del ERP que se usa | Notas |
> |---|---|---|
> | `monitoreo.unidades` | `cms_unidades` | Fuente única de la flota GPS |
> | `reactivo.cuentas` | `cliente_b2b_accounts` | Cuentas B2B |
> | `monitoreo.clientesid` | `iquo_cliente` | Cliente final |

---

## Resumen del dominio nuevo

Se agregan **15 tablas** organizadas en 4 grupos:

| Grupo | Tablas |
|---|---|
| Operativos | `monitoreo_preventivo`, `monitoreo_reactivo`, `monitoreo_historial` |
| Emergencias (Centinela) | `anem_alerta`, `anem_estatus_log`, `wialon_bridge_inbox` |
| Bitácora de cámaras | `monitoreo_camara`, `bitacora_camara`, `bitacora_seguimiento`, `bitacora_contacto` |
| Catálogos auxiliares | `monitoreo_contactos`, `monitoreo_vehiculos`, `monitoreo_operadores`, `monitoreo_ubicaciones`, `monitoreo_stage` (+ `reactivo_stage`) |

## 1. Operativos

### 1.1 `monitoreo_preventivo`

> Monitoreo programado de un viaje (origen → destino). Equivalente al
> modelo Odoo `monitoreo.monitoreo`.

**Columnas principales:**

| Columna | Tipo | Nulo | Notas |
|---|---|---|---|
| `id` | BIGINT | NO | PK |
| `name` | VARCHAR(64) | NO | Folio autogenerado por secuencia, default `"Nuevo"` |
| `company_id` | INTEGER | NO | Tenant (multi-compañía) — index |
| `monitorista_id` | INTEGER | SÍ | FK → `usuarios.id` |
| `origen_id`, `destinoIntermedio_id`, `destino_id` | INTEGER | SÍ | FK → `monitoreo_ubicaciones.id` |
| `stage_id` | INTEGER | SÍ | FK → `monitoreo_stage.id` |
| `tipo_viaje` | VARCHAR(20) | SÍ | enum: `local`/`foraneo` |
| `inicio`, `finalizados` | TIMESTAMPTZ | SÍ | `inicio` default `now()` |
| `cliente_id`, `cliente_final` | INTEGER | SÍ | **FK → `iquo_cliente.id`** (sustituye `monitoreo.clientesid`) |
| `cuenta_id` | INTEGER | SÍ | **FK → `cliente_b2b_accounts.id`** (sustituye `reactivo.cuentas`) |
| `unidad_id` | BIGINT | SÍ | **FK → `cms_unidades.id`** (sustituye `monitoreo.unidades`) |
| `no_serie` | VARCHAR(50) | SÍ | VIN (computed desde unidad, store) |
| `nombre_b2b` | VARCHAR(255) | SÍ | computed desde unidad |
| `tracto_id`, `remolque_id` | INTEGER | SÍ | FK → `monitoreo_vehiculos.id` |
| `chofer_id` | INTEGER | SÍ | FK → `monitoreo_operadores.id` |
| `telefono` | VARCHAR(50) | SÍ | related `chofer_id.telefono` |
| `estado_unidad`, `estado_caja` | VARCHAR(40) | SÍ | enums |
| `llamar_operador`, `actualizacion_gps`, `boton_panico`, `paro_motor`, `apertura_puertas`, `contacto_cliente` | BOOLEAN | NO | pruebas GPS, default `false` |
| `comentarios_pruebas` | TEXT | SÍ | |
| `folio` | INTEGER | NO | folio Centinela, default `0` |
| `fecha_hora_robo`, `modo_robo`, `entidad_robo`, `estado_robo`, `estatus_actual`, `observaciones_robo` | varios | SÍ | campos del evento de robo |
| `active` | BOOLEAN | NO | default `true` · index |
| `created_at`, `updated_at` | TIMESTAMPTZ | NO | auto |

---

### 1.2 `monitoreo_reactivo`

> Monitoreo no programado, abierto a petición del cliente. Equivalente
> a `monitoreo.reactivo`. Comparte la mayoría de campos de robo con
> `monitoreo_preventivo`.

**Específicos:**

| Columna | Tipo | Notas |
|---|---|---|
| `id`, `name`, `cliente_id`, `cuenta_id`, `unidad_id`, `no_serie`, `nombre_b2b`, `folio` | — | Igual que en `monitoreo_preventivo` |
| `reactivo_stage_id` | INTEGER | FK → `reactivo_stage.id` |
| `solicitud_ids` | M2M | `monitoreo_reactivo_tag` (Many-to-Many con tag table) |
| `inicio_solicitud`, `fin_solicitud` | TIMESTAMPTZ | default `now()` |
| `contacto` | VARCHAR(255) | |
| `contactos_autorizados` | TEXT | |
| Campos de robo | — | Iguales a `monitoreo_preventivo` |

**Tablas M2M auxiliares:**
- `monitoreo_reactivo_tag` (catálogo de etiquetas de solicitud)
- `monitoreo_reactivo_solicitud_rel` (M2M con `monitoreo_reactivo`)

---

### 1.3 `monitoreo_historial`

> Bitácora de entradas de seguimiento de un monitoreo (preventivo o
> reactivo). Equivalente a `monitoreo.historial`.

| Columna | Tipo | Nulo | Notas |
|---|---|---|---|
| `id` | BIGINT | NO | PK |
| `monitoreo_id` | BIGINT | NO | FK → `monitoreo_preventivo.id` `ON DELETE CASCADE` |
| `fecha_actualizacion` | TIMESTAMPTZ | NO | default `now()` |
| `monitorista_id` | INTEGER | NO | FK → `usuarios.id` |
| `seguimiento` | VARCHAR(40) | SÍ | enum (14 valores) |
| `comentario` | TEXT | SÍ | |
| `evidencia` | TEXT | SÍ | URL/S3 key |
| `created_at` | TIMESTAMPTZ | NO | `now()` |

**Orden por defecto:** `created_at DESC`.

## 2. Emergencias (Centinela / ANERPV)

### 2.1 `anem_alerta`

> Reporte de alerta crítica. **Bifurcada**: pertenece a un
> `monitoreo_preventivo` **o** a un `monitoreo_reactivo` (XOR).

| Columna | Tipo | Nulo | Notas |
|---|---|---|---|
| `id` | BIGINT | NO | PK |
| `monitoreo_id` | BIGINT | SÍ | FK → `monitoreo_preventivo.id` `ON DELETE CASCADE` · index |
| `reactivo_id` | BIGINT | SÍ | FK → `monitoreo_reactivo.id` `ON DELETE CASCADE` · index |
| `cliente_id`, `cuenta_id`, `unidad_id`, `nombre_b2b` | — | computed de la fuente, store, readonly |
| `no_serie` | VARCHAR(50) | SÍ | VIN computed, **editable si vacío** |
| `folio` | INTEGER | SÍ | folio Centinela, computed-store readonly |
| `reported_at` | TIMESTAMPTZ | NO | default `now()` |
| `placa` | VARCHAR(20) | NO | **required** |
| `marca` | VARCHAR(50) | NO | **required** |
| `anio` | VARCHAR(4) | NO | **required** |
| `submarca` | VARCHAR(50) | SÍ | modelo real |
| `modelo` | VARCHAR(50) | SÍ | legacy ≈ año |
| `color` | VARCHAR(30) | SÍ | |
| `bridge_session_id` | VARCHAR(64) | SÍ | sesión de tracking en el bridge · index · `copy=false` |
| `unidad_last_pos_timestamp` | TIMESTAMPTZ | SÍ | related desde `cms_unidades`, readonly |
| `unidad_dias_sin_posicion` | INTEGER | SÍ | related desde `cms_unidades`, readonly |
| `mongo_data_found` | BOOLEAN | NO | flag de origen de datos, default `false` |

**Constraint XOR**: `CHECK ((monitoreo_id IS NULL) <> (reactivo_id IS NULL))`.

---

### 2.2 `anem_estatus_log`

> Cronología de estatus de la emergencia recibidos desde Centinela.

| Columna | Tipo | Nulo | Notas |
|---|---|---|---|
| `id` | BIGINT | NO | PK |
| `monitoreo_id` | BIGINT | SÍ | FK → `monitoreo_preventivo.id` · index |
| `reactivo_id` | BIGINT | SÍ | FK → `monitoreo_reactivo.id` · index |
| `status` | VARCHAR(30) | NO | enum: `RECIBIDO`, `VALIDO`, `SEGUIMIENTO`, `TERMINADO`, `CANCELADO`, `EN_PROCESO`, `ATENDIENDO`, `EN_SITIO` |
| `date` | VARCHAR(20) | SÍ | `dd/mm/yyyy HH:MM:SS` (texto, como llega de Centinela) |
| `msg` | TEXT | SÍ | mensaje |
| `created_at` | TIMESTAMPTZ | NO | `now()` |

---

### 2.3 `wialon_bridge_inbox`

> Bandeja de entrada con idempotencia para los eventos que el
> wialon-bridge empuja al backend (webhook).

| Columna | Tipo | Nulo | Notas |
|---|---|---|---|
| `id` | BIGINT | NO | PK |
| `event_id` | VARCHAR(64) | NO | **UNIQUE** · index |
| `event_type` | VARCHAR(40) | NO | index |
| `received_at` | TIMESTAMPTZ | NO | default `now()` |
| `processed` | BOOLEAN | NO | default `false` |
| `processed_at` | TIMESTAMPTZ | SÍ | |
| `payload` | JSONB | SÍ | JSON crudo del evento |
| `error` | TEXT | SÍ | si hubo error al procesar |
| `tracking_session_id` | VARCHAR(64) | SÍ | index |

### 4.3 Etapas (kanban)

Todas tienen `id`, `name`, `sequence`, `active`:

- `monitoreo_stage` (etapas del monitoreo preventivo)
- `reactivo_stage` (etapas del monitoreo reactivo)
- `vehiculo_stage` (etapas de un vehículo)
- `camara_stage` (etapas de una cámara)
- `bitacora_stage` (etapas de bitácora de cámara)
- `acceso_stage` (etapas de control de acceso, si se incluye)

## 5. Diagrama entidad-relación (resumen)

```
iquo_cliente (cliente final, en ERP)
   ├── cliente_b2b_accounts (cuenta B2B, en ERP)
   │       └── cms_unidades (unidad GPS, en ERP)
   │
   ├──< monitoreo_contactos
   │
   ├──< monitoreo_preventivo ───< monitoreo_historial
   │        │
   │        └──< anem_alerta ───< anem_estatus_log
   │
   └──< monitoreo_reactivo ───< anem_alerta (XOR monitoreo/reactivo)
            │
            └──< monitoreo_contactos (rel reactivo_id)

monitoreo_camara ──< bitacora_camara ──< bitacora_seguimiento
                                       └──< bitacora_contacto
                                       └──> camara_tag (M2M)

wialon_bridge_inbox  (idempotencia de eventos entrantes del bridge)
```

## 7. Sincronización con el wialon-bridge

El servicio Central de Monitoreo **no escribe en `cms_unidades`/
`cliente_b2b_accounts`** desde su lógica de negocio. La actualización del
catálogo viene del **cron de sync** (HU-70):

```
05:00 CDMX  → sync_cuentas    (bridge → cliente_b2b_accounts)
05:10 CDMX  → sync_unidades   (bridge → cms_unidades)
```

Las unidades que dejan de venir del bridge se desactivan (`active=false`).

## 8. Integración Centinela (datos persistidos)

| Operación | Tabla afectada |
|---|---|
| Levantar folio (HU-75) | `anem_alerta.folio`, `anem_estatus_log` (RECIBIDO) |
| Mantener seguimiento (HU-76) | Sin write en BD propia (el bridge mantiene su estado) |
| Cambio de estatus (HU-77) | `anem_estatus_log` (nuevo registro), `wialon_bridge_inbox` (event_id idempotente) |
| Cierre automático (HU-78) | `anem_estatus_log` (TERMINADO) |
| Detalle del robo (HU-79) | `monitoreo_preventivo`/`monitoreo_reactivo` campos `*_robo` |
