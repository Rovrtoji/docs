Contexto y planeación

Origen

El plan v2.1 nace del cierre del backoffice tras adoptar UUI v8 (Untitled UI) como kit de componentes oficial. Antes de tocar código, el usuario fijó decisiones de diseño:

  • Roles con role_applications plano (sin sub-aplicaciones)
  • Notificaciones backend reales mínimas (no placeholders)
  • Catálogos enlazados a usuarios vía FK position_id y manager_user_id

El plan Hub v2 es paralelo: el hub (apps internas, puerto 5173) había quedado atrás del patrón UUI y necesitaba migración visual y refactor del launcher.

Cambios transversales

Fix CSRF en handoff (post-cierre)

Commit: 8fb4874.

Bug detectado durante prueba real: el botón "abrir app" del launcher no enviaba X-CSRF-Token al POST /api/v1/auth/handoff. El backend respondía 403 csrf token missing or mismatched y el catch del hub caía al fallback silencioso window.location.href = app.base_url, dejando al usuario en bucle hub → app sin sesión → hub.

Solución:

  • Import de readCookie, CSRF_COOKIE_NAME, CSRF_HEADER_NAME desde @finanzas/api-client
  • credentials: 'include' en el fetch
  • Header X-CSRF-Token leído de la cookie csrf_token

Verificado end-to-end con Chrome DevTools MCP: login con ricardo / Jona050311 → click Finanzas → llega a localhost:5175 con sesión iniciada y sidebar completo.

Cierre

Decisiones técnicas que el equipo debe conocer

Estas decisiones quedaron grabadas en memoria persistente y aplican a cualquier trabajo futuro sobre estas áreas:

  1. Cookie httpOnly + CSRF double-submit (F3-02b) es el patrón oficial de auth. No usar Bearer token en frontend ni guardarlo en localStorage.
  2. UUI Input type="password" ya trae toggle nativo de ojito. No agregar botón manual (causa duplicación del Fix D-4).
  3. GET /api/v1/roles devuelve {id:int, nombre:str} (no name). Las interfaces TS deben coincidir o no matchean.
  4. Select de UUI dentro de <Tabs> crashea con selectionManager al cambiar de panel. Mover el Select fuera del Tabs o dar key dinámica.
  5. catalog_service.{create,update,soft_delete}_position y {create,delete}_area_manager retornan dict. Acceder con pos["id"], no pos.id.
  6. Backend en puerto 8090 debe reiniciarse manualmente para cargar código nuevo (no tiene auto-reload). Esto fue causa de varios falsos negativos en QA.
  7. Token de handoff: SHA256 + TTL 60s + single-use + binding IP/UA. Audit con resource=auth_handoff.
  8. SECURITY_ACTIONS (7): user_delete, role_delete, role_permissions_set, role_applications_set, revoke_session, login_failed, application_delete. Notifican a super_admin + auditor.

Cómo desplegar y probar

Pre-deploy

# Backend
cd finananzaspython
source .venv/bin/activate
alembic upgrade head           # aplica j1a2…user_notifications y j2b3…position_manager
pytest tests/ -q               # debe dar 42/42 PASS

Despliegue

  1. Detener y reiniciar uvicorn main:app --port 8090 (sin --reload en prod).
  2. Rebuildear apps frontend: pnpm build:hub y pnpm build:backoffice.
  3. Servir los bundles con nginx (config ya documentada).

Smoke test post-deploy (10 minutos)

  1. Hub login — /login, ingresar ricardo / <pass>, confirmar redirect a backoffice.
  2. Empleado — usuario sin rol admin → debe aterrizar en /launcher con sus apps.
  3. Launcher — click en Finanzas → debe abrir Finanzas con sesión (sin pasar por login).
  4. Forgot password (hub y backoffice) — flujo idle → sent.
  5. Backoffice notificaciones — disparar role_delete vía API → ver badge en la Bell.
  6. Backoffice users — abrir un usuario, ver Puesto + Jefe directo, abrir modal editar, confirmar Selects pueblan.
  7. Backoffice roles — verificar "Da acceso a: App1, App2" en tab Roles del detail.
  8. Backoffice catalogs — abrir departamentos, confirmar contador "N puestos · M usuarios".
  9. Audit log — GET /api/v1/audit-log?resource=auth_handoff debe mostrar actividad.
